/goal

# VideoCompress Face-Aware Bit Allocation
# 在 100 kbps 硬链路下提升人脸真实有效像素密度和连续清晰度

======================================================================
0. 总目标
======================================================================

当前 VideoCompress rebuild 模式已经基本解决：

- reference PTS future/age 基本语义
- PATCH local-ready
- reference refresh deadline
- STATE/video playout synchronization
- bounded STATE extrapolation
- geometry translation
- stable registration template
- ESRGAN future prefetch
- same-source-frame immutable
- SR handover

本任务不要继续围绕这些已实现机制大规模重构。

当前新的主要视觉问题是：

即使 HUD 显示：

    REFREADY=1
    USED=1/1
    AGE < 450ms
    DROP_REASON=NONE
    MODE=ROI-ESRGAN

人物脸部仍可能长时间明显模糊。

根因假设：

当前发送端为 person 发送的是：

    整个 person bbox
    + 20% margin
        ↓
    最长边 <= 96 px
        ↓
    JPEG <= 800 B
        ↓
    Real-ESRGAN x2

因此有限的 reference bit 被大量用于：

    身体
    衣服
    背景 margin
    手臂/腿部

真正的人脸可能在 reference JPEG 中只占很少像素。

本任务目标：

在不提高 100 kbps 总链路上限、
不增加正常 reference 发送次数、
不放宽 450 ms 时效规则的条件下，

把现有 visual-reference bit
从“整个人平均分配”
重新分配为：

    person → head / face-priority sub-ROI

让人物脸部获得显著更高的：

    source pixel density
    JPEG bit density
    ESRGAN input quality

同时保持：

    H.265 基础视频连续
    STATE/PATCH 时序安全
    100 kbps pacing
    多目标基本公平
    非 person 类目标原有行为

2. 当前必须保留的硬约束
======================================================================

以下约束不得通过“优化”取消。

2.1 总链路

    pacing_bitrate_bps = 100000

必须保持。

不能：

    100k → 120k / 150k

来获得更高清 reference。


2.2 H.265 rebuild profile

当前：

    256x144
    6 fps
    target bitrate ≈ 28 kbps

不要为了 Face ROI：

    降低基础视频 fps
    关闭 H265
    大幅挤压 H265 bitrate


2.3 Reference hard age

继续：

    content AGE <= 450 ms

不能：

    450 → 700/1000 ms


2.4 Future render gate

继续执行当前安全规则。

future reference：

    可以提前 compute
    不能提前 render


2.5 Same-source-frame immutable

同一 source_sequence：

一旦 compose：

    pixels immutable

异步：

    PATCH
    STATE
    ESRGAN

只能影响后续 source frame。


2.6 SR worker

继续：

    1 running
    +
    <= 1 newest pending

禁止无限 SR queue。


======================================================================
3. 第一阶段架构原则：不要增加第二路 reference
======================================================================

本阶段不要实现：

    Person PATCH
    +
    Face PATCH

同时发送。

原因：

当前链路已经接近 100 kbps。

增加第二套 PATCH：

    会增加数据包
    会增加 FEC
    会增加 pacer queue
    可能反过来降低 H265 质量
    可能导致 reference 延迟重新超过450ms

第一阶段必须采用：

    “同一 reference transfer 内重新分配空间 bit”

也就是：

现有 person reference：

    whole-person crop

替换为：

    head-priority crop

每个 track：

仍然只有：

    一个 active reference generation
    一套 PATCH transfer
    同一个 refresh scheduler

正常情况下：

    transfer 数量不得增加。


======================================================================
4. 新增 reference mode
======================================================================

增加配置：

    --rebuild-reference-mode=person
    --rebuild-reference-mode=head
    --rebuild-reference-mode=adaptive

语义：

person：

    完全保持现有整人 reference 行为。

用于 baseline 和 rollback。


head：

    对 person class 强制使用 head-priority crop。
    
    非 person class 仍使用完整 object crop。


adaptive：

    person 满足 head ROI 可靠条件：
        → HEAD
    
    否则：
        → PERSON

非 person：
        → PERSON/OBJECT existing behavior


为了兼容：

代码初次实现时默认保持：

    person

完成自动测试和 A/B 真机验证后，

若 adaptive 达到本 goal 验收标准，

才把 rebuild profile 默认值改成：

    adaptive

不要在验证前直接改变默认行为。

只有本轮验证仍然不足，
才考虑下一阶段真正 Face Detector。

    基于 person segmentation 的 face/head proxy

    face detector 输出。

======================================================================
8. Head ROI 算法第一版
======================================================================

不要简单写：

    person bbox top 25%

应尽量利用现有 segmentation mask。

建议：

8.1 取得 person detector bbox

    B = [x0, y0, x1, y1]
    
    W = x1 - x0
    H = y1 - y0


8.2 首先检查

    W > 0
    H > 0
    
    bbox 与 source 有交集。


8.3 在 person bbox 的上部区域寻找 segmentation foreground

搜索范围：

    y0
    到
    y0 + 0.55 * H

即人物 bbox 上部约55%。


8.4 对 segmentation mask 做行统计

寻找：

    upper foreground

排除纯背景行。

计算：

    foreground top
    foreground x min/max
    foreground centroid


8.5 生成 head/upper-body proxy

建议初始：

    vertical span ≈ person foreground top
                    → bbox top + 0.40~0.45H

horizontal：

    根据 upper foreground x min/max

而不是始终：

    bbox center ± fixed width


8.6 为了包含：

    头发
    耳朵
    下巴
    肩部

加入少量 margin：

建议初始：

    horizontal margin ≈ 10~15%
    vertical margin ≈ 8~12%

注意：

这里不是当前 whole-person 的20% margin。

不要浪费大量 background bit。


======================================================================
9. segmentation 不可靠时 fallback
======================================================================

如果：

    upper mask foreground 太少

或者：

    segmentation mask 不存在

或者：

    upper ROI 非法

不要直接丢 reference。

fallback：

使用 fixed head proxy：

    top = bbox.top
    
    bottom ≈ bbox.top + 0.45H
    
    width ≈ 0.70~0.80W
    
    centered around bbox center

再次 clamp 到 source。


如果 fixed proxy 仍不可靠：

    fallback whole-person reference。


======================================================================
10. Head ROI 有效性条件
======================================================================

至少检查：

    crop_width >= minimum
    crop_height >= minimum

初始建议：

    >= 24 px

但必须配置化或通过测试确认。


如果人物离摄像头过远，

例如：

    proxy 只有 12x15 source pixels

不要声称这是高清 face reference。

记录：

    HEAD_FALLBACK=TOO_SMALL

并使用现有 person crop。


另外检查：

    visible_area / expected_area

若因为人物位于图像顶部边缘：

    head crop 被裁掉太多

也 fallback。


======================================================================
11. 坐标语义非常重要
======================================================================

现有 RB/1 PATCH metadata 已有：

    left
    top
    right
    bottom

和：

    reference_left
    reference_top
    reference_right
    reference_bottom


HEAD 模式下：

第一组：

    left/top/right/bottom

必须是：

    实际发送的 head crop
    在 source image 中的坐标。


第二组：

    reference_left/top/right/bottom

继续保存：

    完整 person detector bbox
    at reference capture time。


不要把第二组也改成 head bbox。

因为 receiver 需要：

    reference full-person detector bbox
        →
    current full-person target bbox

计算：

    translation
    scale

然后把内部 head crop 映射到：

    当前人物头部位置。


这是本轮避免协议大改的关键。


======================================================================
12. 不升级 RB/1 header size
======================================================================

第一阶段不要：

    kRebuildPatchFragmentHeaderBytes 40 → 新尺寸

不要因为 head reference：

增加新的坐标字段。

现有 metadata 已经足够表达：

    sub-crop
    +
    parent detector bbox


如果需要 debug REFKIND，

优先使用：

    RebuildPacket.flags

中的一个未使用 bit。

当前 parity 已使用：

    bit0

因此如果确认没有冲突，

可以定义：

    REBUILD_PACKET_FLAG_PARITY      = 0x0001
    REBUILD_PACKET_FLAG_HEAD_REF    = 0x0002

PATCH DATA HEAD：

    flags |= HEAD_REF

PATCH PARITY HEAD：

    flags |= PARITY
    flags |= HEAD_REF


要求：

旧 receiver 不认识 HEAD_REF 时：

仍然能够把 packet 当普通 reference 使用。

不要修改 protocol version。


如果 flags 会引入不必要复杂度，
也允许第一阶段只通过 telemetry 标记 REFKIND，
功能逻辑不能依赖该 flag。

17. 不增加 refresh cadence
======================================================================

本轮不要通过：

    refresh 334ms
        ↓
    refresh 167ms

提高人脸质量。

Reference cadence 继续由现有：

    capture-time deadline scheduler

控制。


HEAD reference：

    使用同一个 reference generation
    使用同一个 refresh scheduler

不能：

    person 每334ms
    head每167ms

因为这会破坏100kbps预算。


======================================================================
18. 多目标情况下的 face priority
======================================================================

当前 max_targets 可能 >1。

如果：

    person
    vehicle

同时等待 reference，

可以引入 face-aware priority，

但 hard deadline 必须优先于语义等级。


推荐 scheduler：

第一层：

    earliest hard deadline / smallest slack

如果某 track 已接近：

    450ms deadline

不得因为它不是 person 而饿死。


只有当多个 candidate：

    deadline slack 都安全

才优先：

    HEAD_PRIORITY person


可以实现：

    effective_score =
        deadline urgency
        +
        small semantic bonus


禁止：

person 永远占用 reference channel，

导致：

vehicle reference AGE >450。

19. 第一阶段不发送 whole-person context patch
======================================================================

人物 BODY 继续依赖：

    H.265 256x144 base

HEAD reference 只负责：

    high-information upper region

这正是 bit reallocation 的核心。


不要因为：

“脸变清楚但衣服没有以前锐”

又增加一个：

    body JPEG

除非后续 A/B 证明业务必须。

65. 最终成功定义
======================================================================

本任务真正成功不是：

    HUD显示ROI-ESRGAN

而是：

在与原401c9bc相同100kbps链路条件下，

通过：

    FULL PERSON
        ↓
    HEAD-PRIORITY REFERENCE

把现有 side-channel bit
重新集中到人物最有价值的脸/头肩区域，

使：

    ESRGAN输入的人脸真实像素显著增加

同时：

    总带宽不增加
    H265不恶化
    reference不更容易过期
    STATE/CONTENT drop不恶化
    时间连续性不恶化

最终实际画面中的人脸：

    更清楚
    更稳定
    更少长时间模糊

且该改善必须能够通过：

    reference pixel density
    JPEG telemetry
    100kbps wire统计
    A/B视频
    objective metrics

共同验证，
而不是依靠主观描述。
